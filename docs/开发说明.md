# MaaHub 开发说明

这份文档说明 MaaHub 的内部结构和工作原理，方便阅读源码、修改功能或支持新的自动化程序。

## 整体结构

```
┌───────────────────────── MaaHub.exe ─────────────────────────┐
│                                                               │
│  web/（界面，运行在 WebView2 里）                               │
│    index.html  页面骨架                                        │
│    style.css   样式与深浅色主题（CSS 变量）                      │
│    app.js      页面渲染、交互、轮询                              │
│    icons.js    线性图标                                         │
│        │  window.pywebview.api.xxx()  （JS 调 Python，返回 Promise）│
│        ▼                                                      │
│  app.py   Api 类：把后台能力包装成界面可调用的方法                 │
│        │                                                      │
│        ▼                                                      │
│  core.py          Hub：应用列表、进程监控线程、启动/停止、顺序执行   │
│  integrations.py  读取各软件的版本、配置任务，解析日志得到运行动态    │
└───────────────────────────────────────────────────────────────┘
          │ 读取（只读）                     │ 启动 / 结束进程
          ▼                                  ▼
   各自动化程序的 config/、logs/、debug/、interface.json      MAA.exe、m9a.exe …
```

- 界面层用 [pywebview](https://pywebview.flowrl.com/) 承载，Windows 上底层是 Edge WebView2。前端是原生 HTML/CSS/JS，没有框架和构建步骤，改完刷新即可。
- Python 端只依赖 pywebview 和 Pillow（图标处理），其余都是标准库和 `ctypes` 调 Windows API。
- MaaHub 对各自动化程序**只读**：不修改它们的任何文件，只读取配置与日志、启动和结束进程。

## 各文件职责

### app.py：入口与接口层

`main()` 创建 `core.Hub` 和窗口，把 `Api` 实例作为 `js_api` 交给 pywebview。`Api` 的公开方法都能在前端用 `window.pywebview.api.方法名(...)` 调用：

| 方法 | 作用 |
|---|---|
| `bootstrap()` | 首次加载：全部应用（含图标、版本、配置）、设置、是否管理员 |
| `state(since)` | 轮询用：正在运行的进程、当前任务、顺序执行状态、`since` 之后的通知 |
| `update(id, fields)` / `save_app(data)` / `delete(id)` / `reorder(ids)` | 修改应用列表 |
| `launch(id)` / `stop(id)` | 启动 / 停止 |
| `seq_start()` / `seq_cancel()` | 顺序执行 |
| `activity(id)` | 运行动态（任务事件） |
| `logs(id)` / `read_log(path)` | 日志文件列表 / 读取日志末尾 |
| `detect(folder)` / `scan(root)` / `add_many(items)` | 识别与批量添加 |
| `pick_folder()` / `open_folder(id)` / `open_url(url)` | 系统对话框与打开外部链接 |

`_view(app)` 把存储的应用数据加上计算字段（图标、主题色、版本、配置、命令行预览、运行记录）后返回给前端。

### core.py：后台逻辑

- **识别程序** `detect_app(folder)`：按目录特征判断类型：有 `MAA.exe` + `MaaCore.dll` 是 MAA 官方界面；有 `MFAAvalonia.dll` 是 MFAAvalonia；有 `interface.json` 或 `config/mxu-*.json` 是 MXU；其余为通用程序。
- **启动参数** `build_args(app)`：按类型拼接，例如 MXU 是 `--autostart -i <实例> -q`。
- **进程监控** `Hub._monitor()`：后台线程每 1.5 秒用 `EnumProcesses` + `QueryFullProcessImageNameW` 列出所有进程，按 **exe 完整路径**匹配到应用，因此同名程序装在不同目录也能区分，在 MaaHub 之外启动的程序同样能被发现。
  - 运行时长从进程真实的创建时间（`GetProcessTimes`）算起。
  - 通过读取进程令牌的 `TokenElevation` 判断它是否以管理员身份运行。普通权限的 MaaHub 无法结束管理员进程，界面会给出提示。
  - 程序退出时写入一条运行记录（每个应用保留最近 30 条）。
- **顺序执行** `start_sequence()` / `_seq_step()`：一个简单状态机，每个步骤依次经过 `wait → launching → running → done`。启动后 60 秒内没检测到进程记为 `fail` 并跳过；检测到进程退出后启动下一个。
- **图标与主题色** `app_icon()`：优先取 `interface.json` 的 `icon` 或目录里的 `logo.ico`，没有则从 exe 资源里提取最大的图标；主题色取图标中高饱和像素的加权平均色。
- **持久化**：应用列表与设置存在 exe 同目录的 `maahub_apps.json`（写入时先写临时文件再替换，避免写坏）。

### integrations.py：与各软件“贯通”

| 能力 | MAA 官方界面 | MFAAvalonia（如 M9A） | MXU（如 MaaEnd） |
|---|---|---|---|
| 版本 | `MAA.exe` 文件版本；资源版本取 `resource/version.json` 的 `last_updated` | 本体取 `interface.json`；界面版本取 `logs/log-*.log` 里的“程序版本：” | 本体取 `interface.json`；界面版本取 exe 文件版本 |
| 框架版本 | — | `debug/maafw.log` 里的 `Version vX` | 同左 |
| 配置与任务 | `config/gui.new.json` → `Configurations.<名>.TaskQueue`，每项有 `Name`、`IsEnable`、`TaskType` | `config/instances/<id>.json` → `TaskItems`，`default_check` 即勾选状态 | `config/mxu-*.json` → `instances[].tasks`，任务名经 `interface.json` 与语言包翻译 |
| 运行动态来源 | `debug/asst.log` 中 `append_callback` 的 `TaskChainStart / TaskChainCompleted / TaskChainError / AllTasksCompleted` | `debug/maafw.log` 中 MaaFramework 写的 `task start:` / `task end:`（含任务入口名和成功与否） | 同左 |

几点说明：

- MaaFramework 项目的任务定义分散在 `interface.json` 的 `import` 文件里，且部分是 **JSONC**（带注释、尾随逗号），`read_jsonc()` 会先去掉注释再解析。
- 任务中文名：`label` 形如 `$task.xxx.label`，去掉 `$` 后在 `languages.zh_cn` 指向的语言文件里查找。
- `maafw.log` 记录的是任务的**入口节点名**（`entry`），需要经 `pi_task_labels()` 映射回中文任务名。
- 运行动态有缓存：日志文件的修改时间和大小不变时直接返回上次结果。

### web/app.js：前端

- 全局状态在对象 `S` 里（应用、运行状态、当前页面、日志页状态等）。
- 每个页面是一个返回 HTML 字符串的函数：`pageHome`、`pageDetail`、`pageSeq`、`pageLogs`、`pageSettings`，`render()` 负责整页重绘。
- 交互用**事件委托**：元素上写 `data-act="launch" data-id="…"`，由文档级的 `click` / `change` 监听统一分发，不需要逐个绑定。
- 轮询：每 1.5 秒调用 `state()`，只有运行状态、当前任务或顺序执行变化时才重绘；每秒刷新一次计时；详情页和日志页每 2 秒刷新运行动态和日志。
- 所有用户数据插入页面前都经过 `esc()` 转义。

## 支持一种新的程序类型

假设要支持另一种界面框架 `foo`：

1. `core.KINDS` 里加一项：`label`、`profile`（配置的叫法，没有填 `None`）、`autorun` / `quit`（是否支持这两个开关）、`hint`。
2. `core.detect_app()` 里加上识别规则。
3. `core.build_args()` 里加上启动参数的拼法。
4. `integrations.py` 里按需补充：`configs()`（读配置与任务）、`versions()`（版本来源）、`primary_logs()`（日志优先级）、`activity_source()` 与 `_activity()`（运行动态解析）。

基于 MaaFramework 的程序通常只需要前三步。运行动态会自动从 `maafw.log` 读取，任务名也会自动从 `interface.json` 翻译。

## 调试

- 以调试模式运行可打开 WebView2 开发者工具：

  ```bat
  set MAAHUB_DEBUG=1
  .venv\Scripts\python app.py
  ```

- 后台逻辑可以脱离界面单独测试，例如：

  ```python
  import core, integrations
  app = core.new_app("测试", r"D:\Games\M9A")
  print(integrations.versions(app))
  print(integrations.configs(app))
  print(integrations.activity(app))
  ```

## 已知限制

- 运行动态依赖各软件的日志格式，软件大版本更新后可能需要调整解析规则。
- MaaHub 只能“选好配置后启动”和“旁观进度”，不能控制软件内部单个任务的开始与停止。
- 只支持 Windows（进程监控、图标提取等依赖 Windows API）。
